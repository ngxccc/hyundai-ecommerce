# Code Architecture & Design Principles (Frontend & Admin)

## 1. Two-Tier Type Organization & Zero-Drift SSOT

- **Tier 1: Global API Contract (`src/types/api.ts`)**:
  - **100% SSOT for Backend DTOs**: All API response DTOs, query parameters, and sub-entity shapes MUST be derived strictly from `src/types/api-schema.d.ts` (generated by `openapi-typescript`).
  - **Semantic Sub-Type Projections**: Project nested schema entities (e.g. `export type DashboardMetrics = AdminDashboardAnalytics["metrics"]`) directly in `src/types/api.ts`.
  - **Zero Manual Duplication**: NEVER declare manual TypeScript interfaces for data returned by or sent to backend endpoints.
- **Tier 2: Feature UI State Types (`src/features/<feature>/<name>-types.ts`)**:
  - **Strictly for Local UI State**: Dedicated feature type files are reserved ONLY for client-side state not modeled by the backend (e.g. multi-step form schemas, canvas drawing state, modal dialog steps, interactive filter view-models).
  - **Banned Pass-Through Files**: NEVER create shallow `features/<feature>/types.ts` files that merely re-export 1:1 API DTOs. Components, hooks, and actions MUST import wire types directly from `@/types/api`.

---

## 2. Deep Components & Information Hiding

- **Thick Implementation, Narrow Interface**: Design UI components with minimal props that encapsulate layout mechanics, error states, and localized formatting internally.
- **Pull Formatting Downward**: Use centralized formatters (e.g. `formatCurrency`, `formatPrice` in `src/lib/utils.ts`) instead of instantiating `new Intl.NumberFormat` inside render loops.
- **Server Component First (RSC)**: Default to React Server Components (`async function`) for static presentation and data fetching. Add `"use client"` ONLY when state (`useState`), effects (`useEffect`), browser APIs, or event handlers are required.

```tsx
// GOOD: Deep Component (Minimal props, server-rendered with zero client JS bundle)
export async function AdminHeader() {
  const t = await getTranslations("adminDashboard");
  return (
    <header>
      <h1>{t("header.title")}</h1>
    </header>
  );
}

// BANNED: Shallow Pass-Through / Unnecessary Client Directive
("use client");
export const ShallowHeader = ({ title }: { title: string }) => <h1>{title}</h1>;
```

## 3. AHA (Avoid Hasty Abstractions) & Rule of Three

- **Prefer Concrete Duplication Over Wrong Abstraction**: Write UI logic inline until exact repetition across 3 distinct feature views proves an identical invariant.
- **Rule of Three Progression**:
  1. _First occurrence_: Inline JSX and state logic.
  2. _Second occurrence_: Duplicate with localized adjustments.
  3. _Third occurrence_: Extract reusable component into `src/components/ui/` (domain-agnostic) or `src/components/common/` (domain-aware) only when layout invariants, accessibility roles, and props contract are identical.
- **Dissolve Tangled Abstractions**: If a shared UI component requires caller-type branching (`if (variant === 'admin-special-case')`), dissolve the component and inline the JSX.

---

## 4. Multi-Tier Caching & Dynamic IO (Next.js 16)

- **Tier 1: RSC Tree Cache (`cacheComponents: true` / `'use cache'`)**: Cache compiled React Server Component virtual DOM payloads using `cacheLife("minutes")` and `cacheTag("analytics")` for high-cost presentation blocks.
- **Tier 2: Network Fetch Data Cache (`next: { revalidate, tags }`)**: Intercept API fetch calls with tag-based revalidation, transmitting dynamic Bearer tokens while caching HTTP responses.
- **Auth Boundary Isolation**: Never invoke `cookies()` inside a `'use cache'` scope. Extract dynamic request parameters in the parent server page and pass them as plain props.

---

## 5. Command-Query Separation (CQS) & Server Actions

- **Mutations via Server Actions (`"use server"`)**: All write operations (create, update, delete, status transitions) execute exclusively via discrete Server Actions returning standardized `ActionResponse<T>`.
- **Side-Effect-Free Queries**: Data fetching executes via typed Server Component calls (`api.GET`) or read-only loaders with deterministic caching and optimistic client updates.
- **Deterministic Revalidation**: Pair every state-changing Server Action with targeted `revalidateTag(...)` or `revalidatePath(...)` to invalidate both RSC tree and fetch caches simultaneously.

---

## 6. YAGNI & Zero Speculative Code

- **Active Requirements Only**: Build solely what active specifications and user flows dictate.
- **Banned Speculations**: Unused component props, dead variant styles, unused utility functions, and speculative client-state stores with a single consumer.

---

## 7. Enterprise Performance & Bundle Optimization (6 Pillars)

- **Pillar 1: Server-First & Partial Prerendering (PPR)**:
  - Default $80-90\%$ of page logic to React Server Components (`async function`) to keep First Load JS $< 100\text{ kB}$.
  - Wrap dynamic request-bound data streams in `<Suspense fallback={<Skeleton />}>` inside root/feature layouts to enable instant static shell prerendering (`cacheComponents: true`).
  - Dynamically import heavy UI modules (`next/dynamic` or `await import(...)`) on user interaction or explicit route navigation.
- **Pillar 2: Bundle Hygiene & Tree-Shaking**:
  - Banned exporting heavy libraries (e.g. `@react-pdf/renderer`, `exceljs`, chart canvases) through general component barrel `index.ts` files.
  - Configure `experimental.optimizePackageImports` for all icon sets and headless UI primitives (`lucide-react`, `@radix-ui/*`, `react-hook-form`, `recharts`).
  - Leverage native ES2024 / Web APIs (`Intl.NumberFormat`, `Intl.DateTimeFormat`, `StructuredClone`, `Array.groupBy`) over heavy polyfill libraries.
- **Pillar 3: Multi-Tier Caching Pipeline**:
  - Tier 1: Edge CDN HTML Shell caching.
  - Tier 2: Next.js 16 `'use cache'` with `cacheLife` & `cacheTag` for compiled RSC trees.
  - Tier 3: Distributed Redis In-Memory caching for complex aggregated backend queries.
  - Tier 4: Selective client-side prefetching (`<Link prefetch={false}>` for low-intent links).
- **Pillar 4: Asset & Typography Pipeline**:
  - Serve modern image formats (`AVIF` / `WebP`) with explicit responsive `sizes` to prevent over-fetching on mobile devices.
  - Self-host fonts via `next/font/google` with character subsetting (`vietnamese`, `latin`) to eliminate font layout shifts ($\text{CLS} = 0$).
- **Pillar 5: CI/CD Performance Budgets**:
  - Enforce zero build-time regression: No single feature PR may increase shared first load JS by $> 5\text{ kB}$.
  - Maintain Core Web Vitals targets: $\text{LCP} < 1.2\text{s}$, $\text{INP} < 100\text{ms}$, $\text{CLS} < 0.05$.
- **Pillar 6: Off-Main-Thread Processing**:
  - Delegate heavy document parsing, batch file generation, or massive catalog filtering to Server APIs or dedicated Web Workers to ensure a consistent 60/120 FPS UI thread.
